# alex with the prelude rules

[alex 3.5.1.0](https://hackage.haskell.org/package/alex-3.5.1.0), built from
its sdist by the `haskell_binary` rule of the buck2 prelude.

```bash
$ buck2 run //examples/prelude/alex:alex -- --version
$ buck2 test //examples/prelude/alex:
```

The test runs alex on one of the examples of the sdist.

## From `alex.cabal` to `BUCK`

The prelude rules know nothing about cabal, so each field of the `executable
alex` stanza has to be translated by hand:

| `alex.cabal` | `BUCK` |
| --- | --- |
| `hs-source-dirs: src`, `main-is`, `other-modules` | `srcs`: one file per module, keyed by its module path (`Data/Ranged.hs`, not `src/Data/Ranged.hs`), taken from the archive as subtargets |
| `build-depends: base, array, containers, directory` | `toolchain_libs`, from the wrapper in `rules/haskell/defs.bzl`: `-package` flags for compiling and linking |
| `default-language`, `default-extensions` | `-X` flags in `compiler_flags` |
| `Paths_alex` (generated by Cabal) | a `cabal_paths_module` target |
| `data-dir`, `data-files` | nothing: the prelude does not install anything |

The last row is the weak spot. `Paths_alex` says the templates are in `data`,
a relative path that means nothing at run time, so alex only finds them when
`alex_datadir` points at the `data` directory of the sdist, as
[`tests/alex.sh`](tests/alex.sh) does.

Compare with [`../../cabal_simple/alex`](../../cabal_simple/alex), where the
same stanza is transcribed field by field and the data files work.
